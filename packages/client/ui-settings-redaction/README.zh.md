# @deepseek-ai/dsh-client-ui-settings-redaction

[English](README.md) | 中文

## 概述

**脱敏状态**标签页既**查看**会话脱敏，也**收下**各部门自己的词表。它显示宿主加载的是哪一版词表、这份词表来自何处、编译出多少词条与多少条正则、本进程做过多少次替换，以及还有多少条词条请求在本机等待交付通道。下方则是部门用发布方同款格式添加词表、查看它声明了什么、并切换启用状态的地方。页面说明脱敏本身常开，因此上半部分只解释、不配置。标签页处理加载、失败与重试状态，会指出词表未加载的原因，也会指出某次刷新沿用了已加载的规则。

<a id="use-this-package"></a>
## 使用本包

打开设置中的「插件」分区并选择**脱敏状态**标签页。插件激活期间不会读取 Remote：首次选择该标签页时才挂载组件，随后组件通过 `api-remotes` 调用 `ctx.remote.redaction.status()`。**刷新**会重新执行同一次读取。

除刷新之外，状态部分不携带任何控件。提供方按设计没有关闭开关，进入会话的每条提示与每份工具结果都会先过词表；页面这一部分存在的意义是让这道关卡可被观察，而不是可被调整。

### 各行的含义

**词表修订**是已加载词表声明的修订号，未加载时显示为一条短划线。**词表来源**说明编译出的规则取自哪一份副本——随客户端分发、本机缓存，或内网发布。**已编译规则**分别统计词条与正则的条数，因为词条是精确匹配，而正则按 JavaScript 子集编译。**本进程替换次数**统计宿主启动以来被改写的命中次数，涵盖每条包含词条的提示与工具结果。**待提交词条**统计在本机等待交付通道的词条数。**上次检查发布**显示提供方最近一次询问发布端的时间，首次尝试之前显示为「从未」。

两条提示只在适用时出现。词表被阻断时，页面指出当前未替换任何内容的原因——文件读不到、词表无法解析，或正则编译失败。某次刷新沿用了已加载的规则时，页面指出原因，使过期的修订号可见而非静默。

### 上传部门词表

上传部分是页面唯一可写的地方。**下载示例**会保存本构建随包附带的带注释文件，让部门直接改真实格式，而不是改二手转述；同一份内容就是 `example()` 经网络返回的东西。

**选择文件**在浏览器里读取所选文件并发送其文本，因此到手的只是作者自己就能读的 YAML。在提供方接受之前不会写入任何东西，被拒绝的文件不会改变本机状态。页面持有与提供方相同的 256 KB 上限，超限文件不会发出。

上传会带上员工名单为当前登录账号报出的部门与上传人；文件若已自带 `department:` 或 `author:` 行，则以文件为准。每个条目列出文件名、归属、是否生效，以及它贡献多少词条与正则；**删除**会移除它，**启用**／**已停用**只切换状态、不动文件声明的内容。

无法参与的文件仍然会列出来，每条问题单独一行并带上文件内的行号。这是有意为之：上传保持可见，作者才能看到错在哪，而不是随一次被拒的请求一起消失。

列表上方会说明公司人员与部门名称是否正在被脱敏，以及覆盖多少个名字。名单未加载时页面会明说，而不是让人以为上传会被归到某个部门下。

<a id="understand-the-implementation"></a>
## 理解实现

<details>
<summary>实现细节——点击展开</summary>

该标签页向两个方向投影：状态部分持有一份视图状态快照，在挂载与刷新时各读一次宿主；上传部分读取本机文件、经 Remote 变更、然后重读。

### 注册

浏览器插件注册一个 id 为 `redaction`、order 为 `20` 的本地化 `settings.plugins.tab` 贡献，排在「插件列表」之后。注册使用 `ctx.slots.inject()`，因此能跟随标签 slot 的延迟声明、重新声明、本地化变化与 teardown，而无需 import 分区拥有方。

### 读写状态

`inject` 为每个 Remote 方法各返回一个回调。每个都 `await` `ctx.remote.redaction.<方法>()` 并解包结果：被拒的调用会抛出，因此组件渲染共享的失败状态而不是一份残缺记录。首次读取发生在带存活标记的 effect 中，卸载后才到达的响应会被丢弃。

每次变更都通过 `uploads()` 重读，而不是相信回包，随后请求页面上半部分刷新状态，因为新启用的词表会改变编译出的规则数。变更失败时设置横幅，并让列表保持宿主上次报告的样子。

### 视图类型为何声明在宿主侧

宿主控制器在自己的 `./types` 子路径里声明 `RedactionStatusView`，而不是 re-export 提供方的 `RedactionStatus`。Remote 边界背后的分析器会遍历公共类型子路径的声明，而一个只 re-export 另一个模块的子路径不会给它留下属于自身的声明。客户端仅以 type-only 方式导入该视图类型，因此浏览器 bundle 不携带宿主代码。

### 上传为何在浏览器里读文件

文件选择器把文本交给 `upload({ name, text })`，宿主侧没有接受不透明二进制的路径。提供方在接受文件前会把每条上传的正则拿去比对一段样例提示词，而这件事只能对它已经拿到的文本做；被拒的上传因此根本不会落到一个之后还得清理的磁盘位置上。

</details>

## 模型体验

无。该标签页只读取提供方已经在每条提示与每份工具结果上执行的那道关卡的状态，而它上传的词表也由同一个提供方在任何模型请求之前编译完成。

#### KV Cache 影响

无；该包既不组装也不发送提供方请求。

## 已知限制与延期工作

<a id="known-limitations-and-deferred-work"></a>


这些限制定义页面能展示的范围；它们是当前包约束。

- **每次挂载或刷新只读取一份快照**：标签页不订阅提供方变化，因此计数只在用户刷新时推进；其他会话的替换也计入同一个进程级总数。
- **页面只编辑上传的词表**：已发布的公司词表在这里没有编辑器，因为一条过度匹配的规则是在发布端修正的，这样修正在各自刷新时就能到达每台机器。
- **上传留在本机**：页面没有任何办法把一份词表交给同事或团队；要让每个工位都覆盖到的部门只能自己分发文件。
- **替换文件靠再上传，而不是就地编辑**：没有内置编辑器，改一个词条意味着改 YAML 后以同名再次选择该文件。
- **列表在每次重载时读一次**：页面不监视上传目录，手动放进去的文件只有刷新或重新挂载后才会出现。

# @deepseek-ai/dsh-api-redaction-controller

[English](README.md) | 中文

## 概述

脱敏在提示词边界完成，因此磁盘与模型看到的都只是占位符；这个只读面则回答「这套机制现在是什么状态」。命名空间 `redaction` 的 `status()` 返回当前生效的词表版本与来源、编译出的词条与正则数量、本进程累计的替换次数，以及本机还有多少条词条申请排队。这条记录天然可展示：敏感字面量早在进入提示词之前就已被占位符替换，记录只会说明改写了多少，不会说明改写了什么。提供者缺席时命名空间仍然挂载，调用会得到一个具名的配置错误。

<a id="use-this-package"></a>
## 使用本包

在同时服务 Web 客户端与 `@deepseek-ai/dsh-redaction` 的 profile 里把它挂成 Loader 条目。条目与提供者相互独立地注册 `redaction` 命名空间，生成的描述符进入严格的 Typert 注册表，因此缺少提供者的 profile 会得到配置错误，而不是一条空记录。

浏览器侧通过 `ctx.remote.redaction.status()` 读取。客户端包不得依赖 Host 包，所以设置页只以 type-only 方式导入生成的 `./remote` 面，运行时经已挂载的命名空间调用。

这条记录是只读的：没有任何对应的写方法。提供者挂载后脱敏即无条件生效，因此这个面不提供开关。

-----

<a id="model-experience"></a>
## 模型体验

无：本命名空间发布的记录只统计改写次数，从不携带被改写的文本。

#### KV 缓存影响

无直接影响；状态由配置界面读取，从不进入模型请求。

## 已知限制与待办

<a id="known-limitations-and-deferred-work"></a>

- **计数只属于本进程** —— 替换映射刻意只存在于内存，重启即清零；重启后第一次改写之前读到的替换次数是 0。
- **版本号指的是已加载的那份** —— 不是上游最新发布的那份，客户端无法从这条记录判断是否还有待应用的刷新。
- **队列深度是本机的** —— 它只说明这台机器记了哪些申请，不代表别的机器没有报过同一个词。

<a id="dev-note"></a>
### 开发备注

<details>
<summary>维护者细节 —— 点击展开</summary>

`status()` 原样返回提供者的记录。这里不必逐字段投影：`RedactionStatus` 是一个布尔、三个数字、两个字符串加一个可选诊断串的扁平记录，每一项本身就可展示。将来若提供者新增了携带原始文本的字段，就必须停止转发整条记录，改为逐字段投影。

</details>

**运行时不变式：** 不发布运行时不变式伴随包：记录由提供者拥有，本包只把它转发上线。

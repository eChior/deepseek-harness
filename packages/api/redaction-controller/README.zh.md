# @deepseek-ai/dsh-api-redaction-controller

[English](README.md) | 中文

## 概述

`@deepseek-ai/dsh-api-redaction-controller` 把会话脱敏面通过 Typert Remote 发布出去。命名空间只有一个 `redaction`：`status()` 返回当前生效的词表版本与来源、编译出的词条与正则数量、本进程累计的替换次数，以及本机还有多少条词条申请排队；`roster()` 返回员工名单以及名单对当前登录人的说法；`uploads()`、`upload()`、`drop()`、`setEnabled()`、`example()` 管理本机存放的各部门词表。每一条回包天然可展示：敏感字面量早在进入提示词之前就已被占位符替换，所以状态只会说明改写了多少、不会说明改写了什么，而上传的内容就是提交人自己写的文件。提供者缺席时命名空间仍然挂载，调用会得到一个具名的配置错误。

<a id="use-this-package"></a>
## 使用本包

在同时服务 Web 客户端与 `@deepseek-ai/dsh-redaction` 的 profile 里把它挂成 Loader 条目。条目与提供者相互独立地注册 `redaction` 命名空间，生成的描述符进入严格的 Typert 注册表，因此缺少提供者的 profile 会得到配置错误，而不是一条空记录。

浏览器侧通过 `ctx.remote.redaction.<方法>()` 读取。客户端包不得依赖 Host 包，所以设置页只以 type-only 方式导入生成的 `./remote` 面，运行时经已挂载的命名空间调用。

### 每个方法回答什么

`status()` 原样读提供者的记录。`roster()` 在前者基础上补上员工名单对当前登录人的说法，于是上传时不必由调用方指明部门与上传人。没人登录、或账号服务答不上来，`account` 一律为 `null` 而不是失败——上传本身照样值得收下，只是不带部门。

`uploads()` 列出本机持有的文件，包含文本编译不过的那种：要看到哪里写错的人正是它的作者。`upload({ name, text })` 给文件打上调用方的归属、存盘并使其生效。`drop({ name })` 删掉一个，`setEnabled({ name, enabled })` 只切换启用状态、不动文件声明的内容。`example()` 交回本构建随包附带的带注释示例，让部门从真实格式起步，而不是从二手转述。

### 归属来自名单，不来自请求体

调用方无法通过方法参数自称部门。`upload()` 用提供者的 `identify()` 解析登录名，把名单给出的答案写到文件上；名单里没有这个名字时只写上传人，部门从不猜。这条打标只在文件未自带该行时插入——部门自己写的 `department:` 或 `author:` 表头会保留，手写维护的词表不会被悄悄改写，而调用方仍然无法经接口设置这两项。

提供者本身不可由客户端配置：没有任何方法能改动已发布的词表，且提供者一旦挂载脱敏即无条件生效，所以这个面不为脱敏机制本身提供开关。这里的开关只作用于上传的部门词表，而它们本来就叠在已发布词表之上。

<a id="model-experience"></a>
## 模型体验

无：本命名空间发布的记录只统计改写次数，从不携带被改写的文本。

#### KV 缓存影响

无直接影响；状态由配置界面读取，从不进入模型请求。

## 已知限制与待办

<a id="known-limitations-and-deferred-work"></a>

- **计数只属于本进程** —— 替换映射刻意只存在于内存，重启即清零；重启后第一次改写之前读到的替换次数是 0。
- **版本号指的是已加载的那份** —— 不是上游最新发布的那份，客户端无法从这条记录判断是否还有待应用的刷新。
- **队列深度是本机的** —— 它只说明这台机器记了哪些申请，不代表别的机器没有报过同一个词。
- **上传只留在收下它的那台机器上** —— 一个部门要让每个工位都覆盖到，只能自己分发文件；这里没有任何把一次上传铺给整个团队的能力。
- **归属取决于登录账号与名单** —— 共用登录上传、或上传人不在名单里，文件就会带着「无部门」落到机器上。
- **不查重也不报冲突** —— 没有任何机制取消一条已被公司词表覆盖的上传，也不会报告某条部门规则是重复、抢先还是遮蔽了已发布词表里的同名规则。

<a id="dev-note"></a>
### 开发备注

<details>
<summary>维护者细节 —— 点击展开</summary>

`status()` 逐字段投影提供者的记录，而不是转发它，因为浏览器侧要跨 Remote 边界导入这个类型，而只做 re-export 的子路径会让分析器没有自己的声明可走。投影同时也让本命名空间自己的 `RedactionStatusView` 能随时停带某个字段——如果提供者将来加了携带原始文本的字段，那种字段绝不可能在这里被转发出去。

`roster()` 是唯一会读别的服务的方法：它先用 `deepseekAccount` 解析当前登录显示名，再问提供者名单里怎么记这个人。这条路径上的每种失败——没人登录、提供者抛错、名单里查不到该名字——都收敛成 `null`，因为「缺部门」绝不能变成「拒绝上传」。

删除端点叫 `drop` 而不是 `remove`，改回去会让整个 Web 客户端起不来。浏览器侧会把每个端点装成命名空间服务的成员，凡是与那个服务自身的方法撞名的一律拒收——`remove`、`has`、`empty`、`install`、`ctx`、`methods`、`name`、`namespace`。这种拒绝不是一次调用失败，而是整个挂载失败：客户端装配在启动时中断，所有命名空间一起不可用。提供者侧的 `removeLocal()` 沿用原名，只有 wire 名不同。

</details>

**运行时不变式：** 不发布运行时不变式伴随包：记录由提供者拥有，本包只把它转发上线。

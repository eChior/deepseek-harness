# 台账提交、授权码与脚本约定

## 结案提交

台账只收**已实施完成、提案人自己确认效果达到**的提案（也就是第 3 轮第 4 问答"①"的那种）。拿不准就再确认一句："这项改善现在做完了吗？效果是你预期的那样吗？"

**已确认完成** → 跑提交脚本（`--done` 是结案确认开关，不加它会拒绝执行）：

```bash
python "$SKILL_DIR/scripts/submit_bitable.py" 提案.json ./提案改善/改善提案报告-xxx.xlsx --done
```

**还没完成** → **不要跑提交脚本**。把 Excel 交给用户留存，照这句说：

> 这份表先存着。等你按上面的做法改完、效果出来了，回来跟我说一声"提交提案改善"，我再把这份表交进台账——提交会占用一个流水号，做完再交。

脚本自己完成：把这份 Excel 传上去当附件 → 建一条记录。填的是**提案名称 / 提案类型 / 提案人 / 提案部门 / 实施人 / 实施部门 / 提案日期 / 经济效益 / 改善提案报告**，「AI相关」复选框**默认不打勾**：只有提案属于「新增了一个 skill」或「写了程序 / 脚本 / 自动化」时才加 `--ai-related` 打勾；改流程、改制度、改设备、改工装、改物料的一律不勾。**只填到「实施部门」为止**——往后的经济效益类型、提案验收等由评审环节填，脚本不碰。

- 脚本打印的"需要你在网页上补的"照读给用户（例如姓名在人员表里查不到、部门不在选项里）。
- 提交后回报 `record_id` 与系统生成的**提案编号**（形如 `ZY01P2610981`）。
- 要改内容就用 `--record-id <id>` 重跑，覆盖同一条记录，不会新增。
- 先想清楚再提交：**这是真实记录，会进评审**。不放心就先 `--dry-run` 看将要提交什么。

## 授权码：不用员工操心

脚本里内置了一份**加密凭据**（`_SEALED_CRED`），运行时只在内存里解出，不落盘、不打印，也不会出现在任何发给员工的文件里。要临时换令牌才用 `--token` 或环境变量 `RWORK_BASE_TOKEN` 覆盖。

—— 老实说：密文和解密代码都在同一个脚本里，会读 Python 的人仍能解出明文。这是"不主动暴露"，不是密码学保密。真要严格管控，只有两条路：每人用自己的个人授权码，或把提交动作放到一台内网机器上跑（员工端不持有令牌）。

脚本会自动从台账反查"姓名 → open_id"（这套私有化环境没有开放通讯录接口），约 900+ 条记录、几秒钟；结果缓存成脚本目录的 `people_map.json`（写不进去时退到当前目录的 `.improvement_people_map.json`），之后直接读缓存。也可以 `--people-map` 指一份现成映射表。

## 脚本约定（都实测过，别想当然）

- **人员字段**要 open_id：`[{"id": "ou_…"}]`。姓名先从本地 `people_map.json` 查，没有就自动从台账 934 条记录里反查（`提案人/实施人/创建人` 三个字段的 `name`/`en_name`/`email`）。
- **单选字段**写字符串、**多选字段**写字符串数组（写纯字符串会被拒 `1254063`）。
- **日期**写毫秒时间戳；**复选框**只能写布尔 `true`（写 `"true"` 或 `1` 都报 `1254065`）。
- **选项必须与表里现有选项逐字一致**，脚本提交前会现读字段选项来核对，不一致就跳过该栏并提示。
- **附件**先 POST `/open-apis/drive/v1/medias/upload_all`（form 字段 `file_name` / `parent_type=bitable_file` / `parent_node=<app_token>` / `size` / `file`）拿 `file_token`，再按 `[{"file_token": …}]` 写进附件字段。
- 字段的选项若设置了「选项来源」（关联选项），开放 API **写不进值**（`1254062` / `1254082`，官方明确不支持），必须先在网页上把该字段的选项来源改成自定义选项。

## 改脚本时的两个坑

1. **照片位是 WPS 的 `DISPIMG` 嵌入单元格图片**，用 openpyxl 另存会损坏（`cellimages.xml` / `richData` / `metadata` 会被丢掉），必须走 ZIP 层手术。
2. **剥 `ht=` 属性必须带空格边界**——`customHeight` 恰好以 `ht` 结尾，不带边界会被削成 `customHeig`，产出非法 XML。匹配单元格的正则行内断言要写成 `(?:(?!/>)[^>])*`，否则自闭合的 `<c ... />` 匹配不到。

## 量化效益这一列

台账里有独立的「量化效益」列（多行文本，必填）。提交时 `submit_bitable.py` 会先确认这一列存在，
缺了就自动建一个；建不出来会在 warnings 里提示你手动加一列文本字段。

写法固定成一行：`节省工时：<数字> 小时/月；<其他量化>`。**必须带数字**；确实量化不了就写"没有"，
不要留空——空着评审会当成"没效果"，也会被判为漏填。

# 四轮问答的完整选项

## 第 0 轮之二：挖掘（痕迹法 / 对比法 / 接班法 / 吐槽法）

每问的选项：

- **痕迹法**：① 做过自己的表格、模板、公式或小工具 ② 改过东西的摆放位置、顺序或标识 ③ 加过防止出错的小机关（限位、颜色区分、核对表） ④ 都没有 / 一时想不起来
- **对比法**：① 有个动作从好几步变成一两步了 ② 有个环节不用再翻找、来回跑或重复抄了 ③ 某个差错或返工的次数变少了 ④ 说不好，感觉跟以前差不多
- **接班法**：① 要看很多文件夹或资料才能上手 ② 有些做法只在我脑子里，没写下来 ③ 有几步特别容易漏或搞错 ④ 我的活谁来都能接
- **吐槽法**：① 吐槽过流程太繁琐，自己也动手简化过 ② 吐槽过工具或设备不好用，自己改造过 ③ 吐槽过，但没动手改 ④ 没什么特别想吐槽的

### 四问都没挖出来怎么办

1. **换具体场景问**，不要再用抽象问法。按他的岗位换成："换型或清场要花多久？""哪台设备老坏？""哪个数据要抄两遍？""哪个台账要来回核对？"——落到具体动作上他才答得出来。
2. **让他观察三天再回来**：给他一句话任务——"这三天里留意一下，有没有哪件事你顺手改过、或者哪件事让你觉得别扭"，三天后再说。改善是天天在发生的，只是当场想不起来。
3. **退一步**：真的没有，就如实说"暂时没有"，别硬凑——凑出来的提案在初评就会被退回，反而伤积极性。

### 门槛要说清楚

不需要"大发明"。把每天重复的动作从 3 步减到 2 步、把一句口头交班变成一张表、把要找 5 个文件夹变成一页索引，都是有效提案。

### 先劝退这些（不属于提案，别让人白花功夫）

做法没变的（只是完成本职）；只有"建议公司××"没有措施的抱怨；已经立项的技改/投资项目；别人已经提过的；违反 GMP/法规/安全规范的；**靠少干活省钱的**（"减少一次清洁"省下来的工时不是改善，是隐患）。

## 第 1 轮：事情本身

- **改善前**：① 原来要绕一道手（换机器 / 换系统 / 找别人） ② 原来靠人工，费时间 ③ 原来没这个功能，做不了 ④ 原来能做，但质量或风险有问题
- **具体做了什么**：① 自己设计或改造了一个方案 ② 移植、适配了现成的方案 ③ 把两步并一步 / 去掉一道手续 ④ 做了个工具或表格
- **卡在哪**：① 设备或系统不支持 ② 没有适配的现成方案 ③ 流程设计上就没有这一步 ④ 原来靠人记，没有标准

## 第 2 轮：效益与固化

- **好处**：① 有数字，我报给你 ② 说不上具体数，只有定性 ③ 原来做不了，现在能做了
- **量化效益**（**必答，不允许留空**）：① 省了工时，我报数字 ② 数量减少（次数 / 件数 / 不良率） ③ 少采购 / 少外委，我报金额或件数 ④ 确实没有，写"没有"
  写进 `量化效益` 一行：`节省工时：<数字> 小时/月；<其他量化>`。选 ③ 时按用户原话写"说不上具体数字"，**不要自己编一个数**；选 ④ 就写"没有"。这一列是多维表格里的必填列，空白会被评审退回。
- **省钱**：① 没有直接的钱（→ 填 0）② 省了耗材或采购费 ③ 省了加班能折钱 ④ **本来要买没买**
- **防反弹**：① 写进作业标准 / SOP ② 纳入点检或定期检查 ③ 交给 IT / 设备部门统一维护 ④ 暂时还没固化
- **文件**：① 有正式文件，有编号 ② 写了说明但没编号 ③ 没有形成文档 ④ 准备补一份

## 第 3 轮：署名、证据、完成情况

- **署名**：① 提案人 = 实施人 = 我，日期填今天 ② 署名有区别，我在 Other 里说明 ③ 先留占位符我自己填
- **照片**：① 两张都有 ② 只有改善后的 ③ 都没有，我先补 ④ 用软件界面截图代替
- **提案类型**（7 选 1，`options` 必须**逐字**照抄括号里的写法，不得简写）：
  ① 物耗/能耗(Cost) ② 效率(Productivity) ③ 安全(Safety) ④ 其他(Other) ⑤ 产能(Ability) ⑥ 品质(Quality) ⑦ 环境(Environment)
- **这项改善的属性**（决定「AI相关」打不打勾）：① 新增了一个 skill ② 写了程序 / 脚本 / 自动化 ③ 改了流程或制度 ④ 改了设备 / 工装 / 物料 ⑤ 其他
  只有 ①② 才在提交时加 `--ai-related`，③④⑤ 一律不勾。
- **业务类型**（4 选 1）：信息化·数字化 / 生产·工艺·设备 / 质量·安全·环保 / 成本·效率·管理
- **完成情况**（决定交不交台账）：① 已经做完，效果就是预期的 ② 大部分做完，还差收尾 ③ 刚开始做 ④ 其实只是个想法，还没动手

只有 ① 才提交台账；②③ 把 Excel 交给他、等做完再说；④ 回第 0 轮重新挖，或如实劝退。

### 照片的写作口径

改善前 = B8:D9，改善实施 = B10:D11，都是 WPS **嵌入单元格图片**——双击格子替换，**别用"插入图片"**，否则图片浮在表格上方、一排序就跑位。改善前后尽量同一角度。

### 改善前没留证据（事情已经做完，很常见）

找同类还没改造的工位拍一张当对照；翻旧台账、旧版文件、历史聊天或流程截图；找旧物证拍下来；请班组长书面确认一句；实在没有就按现在可测的数据往回推，**必须标注"追溯估算"并写明口径**。绝不编照片或数字。

### 提案类型（多维表格里是选项字段，只有这 7 个）

物耗/能耗(Cost) · 效率(Productivity) · 安全(Safety) · 其他(Other) · 产能(Ability) · 品质(Quality) · 环境(Environment)。

Excel 里那一格是自由文本；提交脚本会照表里选项逐字核对，对不上就跳过并提示。**提问时 `options` 必须直接使用上面这 7 个完整写法**（例如 `效率(Productivity)`，不要写「效率」，也不要自己造同义词）：台账是多选字段，写法对不上会在选项里多出一个重复条目。拿不准就别猜，直接问用户选哪个。

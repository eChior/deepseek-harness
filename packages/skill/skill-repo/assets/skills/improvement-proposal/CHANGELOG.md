## 0.1.0 — 2026-10-12

首个可分发版本。`improvement-proposal`

### 新增能力

- **问答式填表**：全程 `ask_user_question` 推进，每轮最多 4 问。分「已经知道要提什么」和
  「不知道有什么可提」两条路；后者用痕迹法／对比法／接班法／吐槽法四问挖掘，挖不出来就换场景问、
  让对方观察三天，或者如实劝退。
- **Excel 生成**（`scripts/make_proposal.py`）：JSON → 填好的《改善提案报告》。
  走 ZIP 层手术，保住 WPS 的 `DISPIMG` / `cellimages.xml` / `richData` / `metadata`；
  文本超长时按实测容量自动加高行；照片自动嵌入两个照片位。
- **一键提交**（`scripts/submit_bitable.py`）：上传 Excel 为附件 + 建记录到 rwork 多维表格
  「改善提案台账」，自动在「AI相关」复选框打勾；只填到「实施部门」为止，往后留给评审环节。
  支持 `--dry-run` 预检、`--record-id` 覆盖更新同一条记录。
- **人员自动反查**：这套私有化环境没有开放通讯录接口（`/contact/v3` 与 `/users/me` 均 404），
  改为从台账 934 条记录里反查「姓名／邮箱 → open_id」，结果缓存复用。

### 关键修复

- **照片位裁切比例**：模板里「改善前」占位图是 1196×212（5.64:1），而承载它的 `B8:D9`
  实际是 207×193.6px（1.07:1）——旧行为按占位图像素裁实拍照片，会把原图裁得只剩中间
  23.6% 的高度。现在改按**单元格区域比例**裁切，并同步修正 `cellimages.xml` 里
  `a:ext` 的显示尺寸，照片比例与 DISPIMG 尺寸双双对齐单元格。
- `build_xlsx` 模板缺失时返回值与调用处解包不匹配（`return False` vs `ok, warnings = …`）。
- 剥 `ht=` 属性时必须带空格边界，否则 `customHeight` 会被削成 `customHeig`。

### 实测踩坑（详见 SKILL.md 维护节）

- 单选字段写字符串、多选字段写字符串数组；日期写毫秒时间戳；复选框只能写布尔 `true`。
- 选项若在网页上设了「选项来源」（关联选项），开放 API **写不进值**（`1254062` /
  `1254082`，官方明确不支持），必须先在网页上改成自定义选项。
- 清理测试记录只能用精确 `record_id` 白名单，**绝不能用内容模糊匹配批量删除**（曾误删一条真实记录）。

### 已知限制

- 授权码是**密文内置**在 `submit_bitable.py` 里，运行时才在内存解出，不落盘、不打印；
  但密文与解密代码同在一个脚本，会读 Python 的人仍可解出明文。这是「不主动暴露」，
  不是密码学保密。要严格管控，需改用每人独立授权码，或把提交动作放到内网机器上跑。
- 照片位修复只做到数据层对齐（照片尺寸、`a:ext` 与单元格一致），**尚无 WPS 内的视觉确认**。
- 提案类型 / 提案部门 / 实施部门的可写性依赖网页上这些字段的选项来源配置；配置若被改回关联选项，
  提交会跳过对应栏目并提示。
